# 轻日历 Changelog 生成器

为「轻 · 日历」项目生成更新日志。

## 触发时机

- 用户说"生成 changelog"、"整理更新内容"、"写更新日志"
- 发布前需要准备 changelog
- 用户想知道本次改了什么

## 工作流程

### 第一步：收集改动来源

从以下渠道综合判断改动内容：

1. **对话上下文**：用户在对话中提到的修改需求（最优先，最准确）
2. **Git diff**：运行 `git diff` 查看未提交的改动
3. **Git log**：如果已提交但未发布，查看 `git log` 最近的提交

### 第二步：分类整理

按以下类别归类改动：

| 类别 | 说明 |
|------|------|
| ✨ 新增 | 新功能、新页面、新模块 |
| 🔧 优化 | 体验改进、性能优化、交互调整 |
| 🐛 修复 | Bug 修复 |
| 🎨 样式 | 纯 UI/视觉调整 |
| ⚙️ 工程 | 部署、脚本、架构调整 |

### 第三步：生成草稿

生成中文 changelog 草稿，每条一行，简洁描述，动词开头。例如：

```
- 新增 Beta 测试计划，支持正式版与 Beta 版切换
- 优化日历月份切换，增加滑入过渡动画
- 修复待办完成时间滚轮越界问题
- 调整"今"按钮位置到左侧
```

### 第四步：用户确认

把草稿展示给用户，问：
- 有没有要补充的？
- 有没有要去掉的？
- 顺序要不要调？（重要的放前面）

### 第五步：输出最终版

确认后，以最终格式输出，可直接用于发布。

## 输出格式

### 用于 README.md 的版本历史格式

```
### vX.Y.Z (YYYY-MM-DD)
- 改动 1
- 改动 2
- 改动 3
```

### 用于发布脚本的格式

用 `` `n `` 分隔的单行字符串，例如：
```
新增Beta测试计划`n优化日历切换动画`n修复时间滚轮越界
```

## 注意事项

- **语言**：始终用中文
- **风格**：简洁、动词开头、不说废话
- **粒度**：每条对应一个用户可感知的改动，不要太细（比如"修复了第 123 行的 typo"就没必要）
- **排序**：重要的放前面，新增 > 优化 > 修复 > 工程
- **不要编造**：不确定的改动不要写进去，宁可少写也不要瞎写
